# TEAM AGREEMENT (Starting Positions)

_This document records **Pierre's initial position** before discussion with Jonathan. These are **proposals, not project decisions**. No position here becomes binding until both developers explicitly agree and the decision is recorded as agreed in this file. Single source of truth for ownership, profit, expenses, legal and tax topics._

## Current status
**PENDING TEAM DISCUSSION.** The following must be discussed and explicitly agreed by both developers:
- Ownership
- Intellectual property
- Revenue sharing
- Expenses
- Responsibilities
- Decision-making
- What happens if one developer leaves
- What happens if the project is cancelled
- What happens if one developer wants to continue alone

## IP Ownership
**Pierre's proposed position.** If both developers genuinely co-create the game with comparable involvement, the default should be **50/50** ownership of the jointly created game and project IP. Work created specifically for the project belongs to the project, not informally to whoever implemented it. Pre-existing IP, libraries, assets, tools or independently created projects remain owned by their original creator unless explicitly transferred or licensed to the project.

**Questions for Jonathan:**
- Is 50/50 ownership acceptable?
- What exactly counts as project IP?
- How should pre-existing code, tools or assets be treated?
- What if one person contributes substantially more work?
- What happens if one person leaves?
- Can one person continue the project alone, and under what conditions?
- What happens to the Steam account, source code, assets and brand?

## Profit Sharing
**Pierre's proposed position.** If ownership and contribution stay roughly equal, the default should be **50/50** profit sharing. The exact definition of "profit" must be agreed before commercial release.

Possible definition:
`Distributable profit = game revenue - platform fees - refunds - taxes owed by the project/entity - directly attributable project expenses.`

No developer may unilaterally classify unrelated personal expenses as project expenses.

**Questions for Jonathan:**
- Is 50/50 acceptable?
- Distribution monthly, quarterly, or only after a reserve threshold?
- Should initial expenses be reimbursed before profit sharing?
- How are future DLC, updates or ports treated?
- What if one person stops contributing after launch?
- What if one developer keeps maintaining the game alone?

## Project Expenses
**Pierre's proposed position.** Reasonable project expenses should be agreed before they are incurred when possible.
- Shared tools or services: default **50/50**.
- Personal tools primarily used by one developer: default paid by that developer, unless both agree it is a project expense.

Examples: AI subscriptions, asset generation, Unity/third-party tools, hosting, Steam-related costs, domain, marketing, contractors, assets.

Large expenses always require explicit agreement from both developers.

**Questions for Jonathan:**
- What spending threshold requires explicit approval?
- Who pays initially?
- How are expenses recorded?
- When are expenses reimbursed?
- What if one person cannot or does not want to finance an expense?

## Legal Entity
**Pierre's proposed position.** Do not create a legal entity prematurely. During experimentation and prototyping, minimize administrative overhead. Before commercial activity becomes significant, choose the appropriate structure based on country of residence, expected revenue, ownership, tax implications, liability, Steam/payment requirements and future commercial plans. Consult a professional before the final legal/tax decision.
**Status: PENDING. No structure selected.**

## Taxes
**Pierre's proposed position.** Do not design a tax structure before there is a concrete commercial situation. Handle taxes according to the actual legal structure and countries involved. Consult an accountant/tax professional before revenue becomes significant.
**Status: PENDING. No tax structure selected.**

## Mandatory discussion: a developer leaving
Resolve this explicitly before the project becomes commercially significant. It is far easier to settle while you are still friends and the game is worth nothing than when it earns real money.

Scenarios to cover:
1. One developer leaves before release.
2. One developer stops contributing but wants to retain ownership.
3. One developer wants to continue alone.
4. Both want to abandon the project.
5. The project succeeds and one developer wants out.
6. One developer becomes unavailable for an extended period.
7. One developer materially stops contributing while the other continues.

For each scenario, define: IP ownership, revenue rights, source-code access, Steam account ownership, brand ownership, right to continue development, and a buyout mechanism if applicable.
**Status: PENDING TEAM DISCUSSION.**

## Mandatory discussion: project accounts
Before commercial activity, determine ownership and access for: GitHub org/repository, Unity org/project, Steamworks account, domain, website, social media, Discord/community, payment accounts, analytics, cloud infrastructure, and AI/tooling accounts where relevant. The goal is to prevent the project from depending on one person's personal account.
**Status: PENDING TEAM DISCUSSION.**

## Decision rule
Until these questions are agreed:
- No assumption of ownership is treated as legally binding.
- No one promises revenue shares to third parties.
- Major project expenses are not incurred unilaterally.
- The project stays technically portable between both developers' environments.
- Important project assets are stored in shared/team-controlled locations where practical.

Final agreements are documented here and, where legally appropriate, formalized in a written agreement.
